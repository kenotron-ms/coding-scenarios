## Steps

### 1. `solution/README.md`

Write a README covering:

**How to run:**
```bash
pip install -r solution/requirements.txt
export PORT=8000
export URLSHORT_DB=/tmp/urlshort.db
python -m solution.main
```

**Explicit ambiguity resolutions (required — acceptance reads these):**

- **A-1 (Idempotency):** Idempotent/dedupe — POSTing the same URL twice returns the same code (201 both times). Clicks are preserved and not reset. Deduplication keys on the verbatim stored URL.
- **A-2 (Code charset/length):** Fixed length 6, base62 alphabet `[0-9A-Za-z]`. Regex: `^[0-9A-Za-z]{6}$`. Codes are generated by drawing 6 random characters from this alphabet using a seeded `random.Random`. Reserved segments (`health`, `api`, `docs`, `redoc`, `openapi.json`, `favicon.ico`) are skipped and redrawn.
- **A-3 (URL normalization):** URLs are stored verbatim — no normalization, no case-folding, no fragment stripping. The `Location` header in 302 responses is byte-identical to the submitted URL. Under A-1(a), deduplication also keys on the verbatim URL.

### 2. `design/openapi.yaml`

Write a valid OpenAPI 3.0.x YAML spec covering all five endpoints. Include:

- `POST /api/shorten` → 201 `{code: string (pattern: ^[0-9A-Za-z]{6}$), short_url: string}` + 400 `{detail: string}`
- `GET /{code}` → 302 (Location header) + 404
- `GET /api/stats/{code}` → 200 `{url: string, code: string, clicks: integer (>=0), created_at: string (format: date-time)}` + 404 `{detail: string}`
- `DELETE /api/{code}` → 204 + 404 `{detail: string}`
- `GET /health` → 200 `{status: string}`

Error responses on `/api/*` use `{detail: string}` (single documented key).

Include the A-2 code pattern as a regex in the schema: `pattern: '^[0-9A-Za-z]{6}$'`.

### 3. `design/DATA_MODEL.md`

Document:

**Schema:**
```sql
CREATE TABLE IF NOT EXISTS links (
    code       TEXT PRIMARY KEY,
    url        TEXT NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    clicks     INTEGER NOT NULL DEFAULT 0
);
```

**Code generation strategy:** Random + collision retry. Draw 6 random base62 characters, attempt INSERT; on UNIQUE constraint violation, retry up to 10 times; if all attempts exhausted, return 500. Trade-off: codes are opaque (not guessable/enumerable), but requires a retry loop and a defined failure mode.

**Atomic increment strategy:** The datastore owns the arithmetic:
```sql
UPDATE links SET clicks = clicks + 1 WHERE code = ?
```
This is executed inside a committed transaction. A SELECT followed by Python +1 followed by UPDATE is the canonical lost-update bug — it fails under concurrent load (NFR-2) because two concurrent reads both see the same value, both add 1, and one update overwrites the other.

**Concurrency model:** SQLite WAL mode (`PRAGMA journal_mode=WAL`) allows concurrent readers. Writes use a threading lock to serialize them, preventing `database is locked` errors under concurrent load.

**Indexes:** The PRIMARY KEY on `code` provides O(log n) lookup for redirects. An optional index on `url` supports A-1 dedupe lookups.

### 4. `design/PRD.md`

Write a PRD-lite covering:

- **Problem statement:** Teams need short, stable, opaque links that redirect to long URLs, with truthful click counts, self-hosted for internal/regulated use.
- **In scope:** URL shortening, redirect, click stats, delete, health endpoint, SQLite persistence, concurrency-safe counting.
- **Out of scope:** Auth, user accounts, custom codes, expiry/TTL, rate limiting, rich analytics, multi-node deployment.
- **User stories:** US-1 through US-7 from REQUIREMENTS.md §1.3.
- **Success metrics:** redirect p95 < 50ms, zero lost clicks under 200 concurrent requests (NFR-2), data survives process restart (FR-10), zero 5xx on documented bad input.

### 5. `design/JTBD.md`

Write Jobs-to-be-done for two roles:

**Integrator:**
- Job: Mint short links programmatically from a bot/service without building link infrastructure.
- Current workaround: Embed raw long URLs (breaks in SMS/print) or use hosted shorteners (unacceptable for regulated data).
- Trigger: Need to send a campaign link via SMS where long URLs break.
- Hired-for criterion: POST returns a short URL I can embed immediately; idempotent retry on timeout doesn't mint duplicates (justifies A-1 dedupe — a bot retrying a timed-out POST must not mint two codes for the same URL).

**Operator:**
- Job: Run the service as a sidecar and know it's healthy without reading source code.
- Current workaround: Manual curl checks, no structured logs.
- Trigger: Deploy or crash event; need to confirm data survived.
- Hired-for criterion: `/health` returns 200 and structured logs confirm the DB path and request outcomes; data and counts survive a restart.
